## Explicit materialization boundaries

- **Synchronous serialization and `JsonRpcResponse.Result` inspection:** these are compatibility escape hatches. They may materialize the complete result. Synchronous serialization blocks on the async iterator without a request cancellation token. A source that requires the blocked synchronization context can deadlock; use the asynchronous HTTP path for incremental sources. No bounded-memory or cancellation guarantee is made for this synchronous use.
- **Persistent event stores:** a store can serialize/materialize the source before the HTTP response and replay it later. HTTP cancellation does not cancel durable event-store ownership. Store capacity and replay identity need separate acceptance; the finite HTTP experiment does not cover them.
- **Custom converters:** explicit `JsonSerializerOptions` retain custom response conversion through the normal serializer. HTTP uses the SDK's fixed JSON metadata context; custom `JsonValue` CLR types without SDK metadata are rejected, as in upstream. Materializing a custom value to a supported JSON node is a supported boundary. Custom converter allocations are outside the bounded scratch guarantee.
- **Non-HTTP transports:** the string API remains supported. Synchronous serialization and complete-message buffering may still occur. The incremental bounded-memory acceptance is specifically the .NET 10 HTTP/SSE route, not a promise for stdio, arbitrary transports or event-store implementations.

## Review findings and disposition

1. The initial Windows CI exposed a test stream override unavailable on net472. The test now supplies the byte-array override and conditionally supplies the modern memory override. Local net472 compilation passes without warnings; no test was skipped.
2. The external Docker `v1` Everything server did not supply the expected sampling test behavior. Tests now run the official server already pinned by `package-lock.json`, drain its output, own/dispose its process and assert the sampling callback. They are regular cross-platform tests rather than manual Docker-only tests.
3. DocFX rejected links to raw experiment evidence that was not registered as a resource. The resources and reproduction link are now explicit; the documentation build retains warnings-as-errors and passes locally.
4. A review probe initially appeared to test custom raw JSON but used a primitive `JsonValue` optimization that did not execute that custom converter. Strengthening the assertion exposed the test limitation. A custom CLR value without SDK metadata is rejected by the fixed serializer context. The retained regression instead verifies supported multiline JSON nodes and their full metadata value; no unsupported custom-converter success is claimed.
5. Two package builds exposed absolute debug paths, random NuGet container metadata and nondeterministic generated logging-source order. Package provenance/reproducibility is documented separately; earlier mismatches are retained rather than mislabeled identical.

No additional runtime defect was established by this review. No serializer, transport, fixture size or memory-limit change was made during the review follow-up, so the previous large workload evidence retains its exact runtime provenance.
